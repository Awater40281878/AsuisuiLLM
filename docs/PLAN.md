# 產品與可行性規劃

## 目標

打造私人、本機優先的助理：搜尋自己的對話與文件、管理工作、以語音交談，並維護可查來源、可審查和可回復的長期記憶。模型只負責理解與草擬；資料讀寫由明確的應用程式功能執行並留下紀錄。

## 可行性

依目前提供的 RTX 3060 12 GB、32 GB RAM，做可用的單人原型可行。中小型量化文字模型、離線語音辨識、中文語音合成都可分別試跑。大型模型、低延遲即時語音、長時間常駐與高品質中文音色需要實測，不能僅由顯卡規格保證。CPU 型號和當下可用 RAM 尚未重新確認。

## 分階段範圍

### 0. 確認基線

- 在 Windows 查明 CPU 型號、RAM、GPU/VRAM、磁碟位置與可用空間。
- 確認開發語言與介面偏好、資料來源，以及模型能否接受離線下載後使用。
- 比較本機模型服務和中文語音辨識／合成的授權、中文效果、速度與磁碟需求。

### 1. 文字助理骨架

- 建立本機應用程式、設定檔和健康檢查。
- 接一個本機模型服務；服務不可用時提供清楚提示。
- 對話以本機 SQLite 保存，可建立及刪除對話。

### 2. 搜尋與工作

- 對話先用全文檢索；文件匯入支援格式和路徑另行定義。
- 工作資料含標題、狀態、到期日、建立與更新時間。
- 工具呼叫採白名單、輸入驗證和操作紀錄；涉及破壞或外部副作用時要求確認。

### 3. 語音

- 先做按鍵錄音、離線語音轉文字、文字回覆和離線語音播放。
- 測量中文辨識、合成音質、端到端延遲與 VRAM/RAM 佔用。
- 常駐喚醒、打斷、串流語音列為後續選項。

### 4. 記憶與復原

- 從使用者明確挑選或核准的內容建立記憶候選，保存來源、時間、信心和狀態。
- 檢視差異與衝突，核准後才更新記憶檔並建立本機 Git 提交。
- 支援查看歷史、撤銷錯誤提交與重建索引；Git 只追蹤小型、去敏感化的記憶檔。
- 自動提交需有穩定評估資料與明確規則後再考慮；遠端推送是獨立、預設停用的功能。

## 建議架構

- 桌面／本機 Web UI：對話、搜尋、工作、記憶審查。
- 應用服務：身分與權限邊界、提示組裝、工具白名單、操作紀錄。
- 模型介面：可插拔的本機 LLM、STT、TTS 適配器。
- 儲存：SQLite 對話／工作／來源中繼資料；全文索引；可選向量索引。
- 記憶：獨立、可讀的 Markdown/JSON 檔與 Git；索引為衍生資料，可重建。

## 主要風險與處理

- 幻覺或錯誤記憶：引用來源、候選草稿、差異檢視、撤銷與稽核紀錄。
- 私人資料外流：本機預設、網路功能關閉、資料目錄排除於 Git、明確匯出。
- 模型品質／資源：先以實際繁體中文資料建立小型評估集，再比較速度與品質。
- Git 誤提交：記憶庫與程式碼庫分離或使用專用子目錄；忽略資料庫、模型、錄音和金鑰；提交前掃描敏感內容。
- 資料損壞或磁碟故障：Git 不等於備份，需另設本機備份及還原演練。

## 第一階段完成條件

Windows 上可啟動介面、能連本機文字模型、對話僅存本機、能查看服務狀態，且模型停用時應用程式仍能啟動並顯示原因。確定模型與框架後再選定具體安裝命令。
